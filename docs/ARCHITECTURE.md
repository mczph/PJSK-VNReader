# 架构说明

## 桌面与浏览器

桌面版由 Electron 主进程、预加载桥接、资源子进程和 React 渲染界面组成。`desktop/main.mjs` 启动 `utilityProcess` 资源服务，用固定的 `sekai://app` 地址向界面提供前端与 API；内部服务只监听随机的 `127.0.0.1` 端口。

渲染进程开启隔离与沙箱，不直接访问 Node.js。`desktop/preload.cjs` 提供存档持久化、窗口操作、数据目录和文件对话框接口。资源服务退出时，桌面提示用户重新启动。

浏览器版直接访问 Express 服务，开发模式由 Vite 代理 API / 资源请求。两种运行方式共用剧本、资源与前端实现。

## 章节与资源准备

1. `server/index.js` 读取 Sekai-World 对应服务器的 master 数据，建立主线 / 活动目录；`server/personal.js` 建立角色介绍及卡片剧情目录。
2. `server/story.js` 将原始脚本解析为对白节点、节点前 / 后的场景快照、Wait / Now 演出事件、引用模型与收尾事件。
3. 准备章节时下载剧本、背景、配音、BGM、封面与出场角色头像，随后准备 Live2D 纹理 / 动作及特效。
4. `/api/jobs/:key` 提供阶段与进度，准备完成后进入播放器。媒体缺失可保留文字阅读，重新准备章节会重试缺失项。

不同服务器的媒体缺失时，`server/resources.js` 只对允许的媒体文件尝试日服相同路径；剧本与本地化文本不会被替换。Live2D 从独立的 `sekai-live2d-assets` 资源桶下载，Cubism Core 按需从 Live2D 官方地址取得。

## 演出与点击

`src/StoryStage.jsx` 按 `src/snippet-timeline.js` 的 Wait / Now 分组执行事件：组内并行，下一组等待上一组完成。演出支持角色布局、动作 / 表情、转场、音效、镜头、视频和全屏文字等。

正常自动阅读等待演出结束、文字显示完整和配音完成，再按自动间隔推进。手动第一次操作补全文字；再次操作中断配音，并用目标节点快照直接恢复场景与动作终态，跳过中间演出等待。中止的异步演出通过 AbortController 失效，避免旧节点覆盖新场景。

每个对白节点拥有独立的语音生命周期。离开节点时暂停并释放该批音频，清除事件处理器和菜单恢复标记；收尾节点没有继承末句语音。播放器离开阅读页时停止旧音频，后台 / 菜单只恢复仍属于当前阅读页的声音。

Live2D 按角色出场实例化，仅更新可见模型；退出章节释放模型及纹理。节能档调整帧率与画布精度，最小化时停止渲染、声音和自动推进。

## 缓存与队列

资源以来源 URL 的 SHA-256 命名保存在缓存目录，避免路径拼接和重复下载。`server/resource-store.js` 保存文件来源、大小、时间及所属章节；多个章节可引用同一缓存文件。

批量队列持久化到 `download-queue.json`，依次准备章节，每章资源内部并发。暂停在当前章结束后生效；重启后队列保留并等待手动继续。

按章节清理删除独占资源，保留共享资源。按文件清理会更新相关章节状态；一键清空清理全部素材缓存与来源映射，同时保留独立的存档 / 设置。下载或准备资源期间不执行冲突的清理。

## 用户数据

| 数据 | 桌面版 | 浏览器版 |
| --- | --- | --- |
| 素材缓存 | 应用数据目录 `cache/` | 服务工作目录 `.cache/` |
| 设置 / 存档 / 已读 / 续读 | localStorage 并镜像到 `reader-state.json` | 当前站点 localStorage |
| 导入字体 | `sekai://app` 的 IndexedDB | 当前站点 IndexedDB |
| 队列和素材索引 | 对应缓存目录 | 对应缓存目录 |

开发桌面版默认也使用工作目录 `.cache/`。存档 JSON 导入 / 导出不包含字体和游戏素材。仓库只上传源码、软件图标、锁定依赖清单、测试与文档，不包含上述本地数据。
